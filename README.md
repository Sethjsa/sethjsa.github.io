# sethjsa.github.io

Personal site and blog, built with Jekyll and served via GitHub Pages at
[sethjsa.github.io](https://sethjsa.github.io). Originally forked from the
[academicpages](https://github.com/academicpages/academicpages.github.io)
template (itself based on Minimal Mistakes), but heavily customized since —
most of the template's original structure is gone.

## Structure

- `index.html`, `cv.html`, `publications.html`, `blog.html`, `now.html` —
  the academic/CV side of the site.
- `outdoors.html`, `indoors.html`, `gallery.html`, `music.html` — running,
  cycling and hiking; music/films/gigs; film photography; and my own
  recordings, respectively.
- `_includes/frags/` — shared page fragments (`nav.html`, `meta.html`) and
  the individual data-driven widgets embedded on the pages above
  (`strava_recent.html`, `summitbag.html`, `squadrats.html`, `lastfm.html`,
  `letterboxd.html`, `concerts.html`).
- `_data/` — YAML/JSON consumed by the widgets above. Most of these files
  are **auto-generated by the scripts and workflows below — don't hand-edit
  them**, changes will be overwritten on the next scheduled run. Each
  generated file's header comment says so explicitly.
- `_posts/` — blog posts for `blog.html`. Draft posts that shouldn't be
  published yet are prefixed `xxxx-` (e.g. `xxxx-05-06-good-life.md`)
  instead of a real date; this prefix is excluded in `.gitignore` so drafts
  never accidentally get committed/published.
- `scripts/` — Python scripts that populate `_data/`. See below.

## Data automation

Four GitHub Actions workflows in `.github/workflows/` run the scripts in
`scripts/` on a schedule and commit the resulting `_data/*.yml`/`.json`
straight back to the repo:

| Workflow | Schedule | Script | Feeds |
|---|---|---|---|
| `summitbag-stats.yml` | daily 06:00 UTC | `update_summitbag_stats.py` | `summitbag.html` (peaks bagged, elevation charts) — pulls Strava activities and parses Summit Bag's auto-appended peak descriptions |
| `media-stats.yml` | daily 06:30 UTC | `update_lastfm_stats.py`, `update_letterboxd_recent.py` | `lastfm.html`, `letterboxd.html` (recent listens/watches) |
| `concert-stats.yml` | weekly, Sun 07:00 UTC | `update_concert_stats.py` | `concerts.html` — scrapes Concert Archives, needs Playwright/Chromium for its Cloudflare check |
| `squadrats-stats.yml` | weekly, Sun 07:30 UTC | `update_squadrats_stats.py` | `squadrats.html` — pulls tile-collecting stats from a StatsHunters share page |

Each workflow also supports manual `workflow_dispatch` for backfills — check
the individual `.github/workflows/*.yml` for available inputs (e.g.
`summitbag-stats.yml` accepts `full_backfill` to rescan all Strava history).

Two additional scripts, `import_letterboxd_export.py` and
`import_rym_export.py`, are **not** scheduled — there's no public API for
full watch/listen history, so these process one-off data exports and are
run manually when needed.

`music.html` is the one exception to the pre-baked-data pattern: it fetches
the track list live from SoundCloud's JS widget API at page load rather
than reading from `_data/`.

Strava's and Squadrats' own embeddable widgets are both effectively dead
(login-walled/broken) — see the commented-out iframes left in place in
`outdoors.html` as a record of what was tried before switching to the
custom pre-baked widgets above.

## Running locally

```
bundle install
bundle exec jekyll serve
```

Serves at `localhost:4000` and rebuilds on file changes. If `bundle install`
complains about a lockfile/security advisory, delete `Gemfile.lock` and
retry.

## Publishing

Push to `master` — GitHub Pages builds and deploys automatically. No CI
build step beyond that.
